# 地图双指缩放设计

## 目标

让对局地图在 iPhone 和 iPad 上都能通过双指捏合稳定地放大和缩小，同时继续支持单指拖动、点击城市与路线，并保持现有侧栏、手牌遮挡边界规则。

## 已确认范围

- 只提供双指捏合缩放，不增加 `+`、`-` 或倍率按钮。
- 放大上限继续使用 `2.8`，缩小下限继续使用 `0.75`。
- 缩放围绕双指中心进行，手指下的地图内容在缩放过程中保持稳定。
- 缩放后的相机位置继续经过现有 `MapViewportInsets` 边界约束，地图不能被移出可操作区域。
- 不改变地图美术、节点坐标、路线拓扑、侧栏或手牌布局。

## 现状与问题

`GameMapView` 已经注册了 `MagnifyGesture`，但它只把倍率乘到当前相机缩放上，始终围绕相机中心缩放。捏合发生在地图边缘时，用户关注的城市会明显偏离手指。现有 UI 测试在执行捏合后只断言地图元素仍存在，没有证明相机倍率或焦点实际发生了正确变化，因此该交互没有可靠的回归保护。

## 设计

### 缩放状态

新增一个轻量、可单元测试的缩放计算单元，接收：

- 手势开始时的语义倍率；
- 当前手势倍率；
- 双指中心在视图中的坐标；
- 当前相机平移量和 `MapViewportMetrics`。

它输出受上下限约束的新倍率，以及为了保持双指中心内容不移动而需要的新相机平移量。计算结果仍交给 `GameMapScene.updateCamera` 做最终边界约束，不复制相机边界逻辑。

### 手势流程

1. 捏合开始时记录相机倍率、相机平移量和双指起点。
2. 捏合变化时，以该次手势开始状态为基准计算倍率，避免累积浮点误差。
3. 根据缩放前后每个屏幕点对应的场景单位差，修正相机平移量，使双指起点下的场景坐标保持不变。
4. 捏合结束时提交经过 `GameMapScene` 约束后的倍率和平移量。
5. 单指拖动仍使用现有流程；空间点击仍只负责城市、路线和贸易商选择。

### 边界与异常情况

- 超过 `0.75...2.8` 的倍率立即钳制。
- 当某个轴上的可见范围大于地图时，沿用现有规则把该轴居中，不保留隐藏偏移。
- 侧栏开合、设备旋转或视口尺寸变化后，使用当前倍率重新计算并约束相机。
- 捏合过程中即使同时收到轻微单指位移，也以缩放锚点计算为主，避免焦点跳动；手势结束后拖动继续正常工作。

## 测试

### 单元测试

- `1.5` 倍捏合确实提高语义倍率并降低 SpriteKit 相机缩放值。
- 以非中心点捏合时，该点对应的场景坐标在缩放前后保持一致。
- 放大、缩小均受 `0.75...2.8` 限制。
- iPhone 遮挡 inset 与 iPad 零 inset 下，缩放结果都保持在合法相机边界内。
- 缩放后拖动换算和目标点击坐标仍正确。

### UI 验收

- 在 iPhone 与 iPad 模拟器中，分别完成一次放大、缩小、拖动和城市点击。
- UI 测试通过可观察的地图相机状态或地图节点位置变化证明捏合生效，不再只断言地图存在。
- iPhone 底部城市仍能拖到手牌上方并点击；iPad 固定侧栏行为不变。

## 完成标准

双指捏合在两类设备上均能连续、稳定地改变地图倍率，缩放中心不跳动，地图始终可拖动和点击，相关单元测试、UI 测试与现有回归测试全部通过。
