# 合法建造选项与地图产业反馈设计

## 问题

真实对局的建造查询先要求玩家选择产业牌，再选择地图落点。当前第一步直接返回玩家六个产业堆顶，没有先验证所选手牌在当前盘面上是否存在合法落点。因此，使用基德明斯特地点牌时，界面会同时显示制造厂、陶瓷厂等最终无法落地的产业；权威规则数据其实只允许该城的棉纺厂与煤矿槽位。

建造完成后，权威快照已经包含产业类型、等级、资源数、翻面状态和所有者，但 SpriteKit 地图标记只绘制所有者颜色与“等级·资源数”。产业类型在渲染阶段被丢弃，玩家无法分辨建成的是煤矿还是其他产业。

## 目标

- 建造流程第一步只显示当前手牌与盘面上至少有一个合法落点的产业。
- 合法性始终由 `BuildRules.legalBuildTargets` 决定，界面不硬编码城市或产业规则。
- 地图上的每个已建产业持续显示明确的产业类型，同时保留等级、资源数、翻面状态与所有者颜色。
- 给 SpriteKit 节点提供可测试的名称和语义数据，便于回归测试与后续辅助功能扩展。

## 方案比较

### A. 查询驱动的合法产业 + 紧凑产业牌（采用）

在 `LegalActionQueryEngine.build` 的首个选择阶段，用 `legalBuildTargets` 过滤产业堆顶；地图标记使用一个中文单字作为类型主标识（棉、制、陶、煤、铁、酒），用小号副标识展示等级与剩余资源。

优点是修复发生在权威规则边界，所有客户端自然一致；地图信息常驻且占用很小。缺点是单字需要配合节点语义数据和稳定的视觉映射。

### B. 显示全部产业并禁用非法项

可以解释玩家为什么不能建，但会继续占据手机底部有限空间，也与“只显示能做的事情”的现有操作流程不一致。

### C. 新增完整城市详情检查器

能够展示所有槽位、规则与产业详情，但明显扩大交互范围，不能直接解决权威查询返回非法候选的问题。

## 详细设计

### 合法建造选项

当建造草稿尚未选择产业牌时：

1. 取得每个产业堆的顶部牌。
2. 对每张顶部牌调用 `BuildRules.legalBuildTargets(actorID:cardID:tile:state:catalog:)`。
3. 只为结果非空的产业牌生成 `LegalChoice`。
4. 保留既有中文名称和类型化的 `.industryTile` 值。

后续选择地点和资源的流程不变。这样过滤会同时考虑地点牌、产业牌、槽位优先级、时代、现金、网络、资源来源和覆盖建造等完整规则，而不只是读取地图槽位。

### 地图产业牌

每个 `MapIndustryPlacement` 绘制为 28×28 的圆角产业牌：

- 主标识：产业中文单字，字号足够在 iPhone 缩放下识别。
- 副标识：`L等级`；有资源时额外显示 `·资源数`。
- 颜色：所有者颜色继续作为填充；翻面后降低填充不透明度。
- 边框：未翻面使用清晰的浅色边框，翻面后使用较细边框。
- 节点数据：补充 `industryKind` 与中文 `industryName`，保留现有 owner、tile、level、resource、flipped 数据。
- 子节点命名：`industry-kind` 与 `industry-detail`，让测试能断言产业类型确实被呈现。

产业牌仍排列在城市节点下方。本次不引入建造完成动画、城市详情页或新的快照字段。

## 测试与验收

- 规则测试构造基德明斯特地点牌，断言初始建造选项只含棉纺厂与煤矿，并且每个返回产业都有合法落点。
- 地图测试构造煤矿放置，断言产业节点显示“煤”，详情包含等级/资源，节点数据包含 `coal` 与“煤矿”。
- 现有建造、地图和真实快照投影测试继续通过。
- 构建 Debug 应用并在 iPhone、iPad 两个模拟器重新启动，供手动走完整建造流程。
