一、Daft 是什么，从哪来

Daft 由初创公司 Eventual 开发。公司 2022 年创立，两位创始人 Sammy Sidhu 和 Jay Chia 是前 Lyft 数据平台工程师，亲历过“机器学习数据管道既不是纯表格、又大到单机装不下”的困境，于是从零写了一个 Rust 内核的分布式查询引擎。团队约 18 人，成员背景包括 Databricks Photon（Databricks 自研的 C++ 引擎）、GitHub Copilot、Pinecone、Render 和 AWS PartiQL。2025 年 6 月公司宣布累计融资 3000 万美元（A 轮由 Felicis 领投，M12、Citi 参投，此前种子轮由 CRV 领投、Y Combinator 参投）。

它与常见框架最大的差异是把“非结构化数据”当成一等公民：图片、视频、音频、张量、embedding 在 Daft 里是原生列类型，可以直接 download → decode → resize → 推理，在 Jupyter 里图片列甚至直接显示缩略图。同时它是惰性执行的声明式引擎，自带查询优化器，这一点像 Spark SQL；但内核是 Rust + Apache Arrow，没有 JVM，启动和 UDF 开销都小得多。

二、它解决什么问题

AI 时代的数据工程现实是：一条训练数据 = 结构化元数据 + 一堆图片/视频/PDF 文件。传统工具链处理这种数据都要“缝”：

传统方案痛点Daft 的回应
pandas / Polars 单机内存受限；图片、视频是“大对象”，处理笨拙 分布式 + 超内存溢写（out-of-core）；图片/张量/embedding 是原生列类型
PySpark JVM 启动慢，Python UDF 序列化开销大，无原生多模态类型 Rust 内核无 JVM；Arrow 零拷贝 UDF；声明式多模态表达式
Ray Data 偏底层算子（map_batches），内存与批处理要自己管 查询优化器 + 流式执行引擎，自动背压、自适应批大小
自写胶水脚本 下载 → 解码 → 推理 → 写库，各环节手工拼接、难扩展 一条 DataFrame 管道全包，本地到集群代码不变

四、核心特性

1. 多模态一等类型

Image、Video、Audio、Tensor、Embedding、URL、JSON、嵌套 List/Struct 都是原生列类型。表达式可以直接链式操作：url.download()、image.decode()、image.resize()、视频抽帧、cosine_distance() 等，Jupyter 中图片列直接渲染缩略图。

2. 内置 AI 算子

prompt() 用 Pydantic 模型定义输出结构，让 LLM 返回强类型字段（接 OpenAI 等托管模型或自托管模型）；embed_text() / embed_image() 生成嵌入；classify() 做批量分类。CPU 解码与 GPU 推理可在同一条管道里混合调度，Daft 负责批处理、重试与容错（如 on_error="null"）。

3. Rust 内核 + Arrow 零拷贝

SIMD 向量化执行、无 JVM。官网口径：启动快 20×、内存占用低 5×、文件下载器快 40×（厂商数字，仅供量级参考）。超出内存的数据自动溢写磁盘，小集群也能跑大数据。

4. 惰性执行 + 查询优化器

所有操作先构建逻辑计划，优化器做谓词下推、投影裁剪、limit 下推（甚至穿过保留行数的 join 侧）后再生成物理计划；explain() 可查看执行计划。这是它区别于“能分布式的 pandas 封装”的根本点。

5. 三种运行器，本地到集群代码不变

默认本地多进程（pip 装完即用）；自研 Flotilla 分布式运行器跑在 Kubernetes 上（每节点一个 worker，内置背压与自适应批大小）；也支持接入 Ray 集群。同一份 DataFrame 代码，开发在笔记本、生产在集群。

6. 连接器生态

读取：S3 / GCS / Azure / R2 / HDFS、Parquet / CSV / JSON / HDF5 / WebDataset、Iceberg / Delta Lake / Hudi（可读写）、HuggingFace 数据集、Kafka、Unity Catalog、Gravitino 目录。写出：Parquet、Iceberg、Delta、Turbopuffer 向量库等。甚至支持机器人领域的 LeRobot 数据集格式。

六、代码实战（示例均取自官方文档 / 官网，注释为中文注释）

示例 1 · 十分钟上手：图片处理 + LLM 结构化推理

来自官方 Quickstart：读 HuggingFace 电商数据集，下载商品图，用 GPT 判断“是否木制品”——整条管道并行执行。

import daft
from pydantic import BaseModel, Field
from daft.functions import prompt, download, decode_image, regexp_extract

# 1. 直接读 HuggingFace / S3 / Iceberg / Delta —— 惰性执行，此刻只解析 schema
df = daft.read_huggingface("calmgoose/amazon-product-data-2020")

# 2. 表达式加工：正则抽出第一张商品图 URL
df = df.select("Product Name", "About Product", "Image").limit(100)
df = df.with_column("image_url", regexp_extract(df["Image"], r"^([^|]+)", 1))

# 3. 多模态算子：下载 + 解码图片，失败置空不中断整个作业
df = df.with_column(
    "image",
    decode_image(download(df["image_url"], on_error="null"), on_error="null"),
)

# 4. LLM 批量结构化推理：用 Pydantic 定义输出 schema
class WoodAnalysis(BaseModel):
    is_wooden: bool = Field(description="该商品是否为木制品")

df = df.with_column("analysis", prompt(
    ["这个商品是木制的吗？请看图判断。", df["image"]],
    return_format=WoodAnalysis, model="gpt-4o-mini", provider="openai",
))
df = df.with_column("is_wooden", df["analysis"]["is_wooden"])

# 5. 触发执行并落盘 Parquet
df = df.collect()
df.write_parquet("product_analysis", write_mode="overwrite")

依赖：pip install -U "daft[openai]" numpy pillow

示例 3 · 语义检索管道：PDF → LLM 摘要 → 向量库

改编自官网「AI Search」示例：从 S3 读 PDF，让 LLM 抽结构化字段，生成 embedding，直写向量库。

import daft
from pydantic import BaseModel, Field
from daft.functions import prompt, embed_text

class Paper(BaseModel):
    title: str = Field(description="论文标题")
    summary: str = Field(description="一句话摘要")

df = daft.from_glob_path("s3://bucket/papers/*.pdf")

df = df.with_column("paper", prompt(
    ["请总结这篇论文：", df["path"]],
    return_format=Paper, model="gpt-5-mini", provider="openai",
))
df = df.with_column("title", df["paper"]["title"])
df = df.with_column("embedding", embed_text(df["title"]))

df.write_turbopuffer("papers-index")   # 写入向量库，语义检索就绪

示例 4 · 扩展到集群

Daft 默认本地多进程执行即可跑满多核；需要更大规模时安装 Ray 扩展 pip install "daft[ray]" 接入 Ray 集群，或用自研 Flotilla 运行器跑在 Kubernetes 上（Flight Shuffle 负责多 TB 级跨节点数据交换）。核心卖点：从笔记本切到集群，DataFrame 代码一行不改。具体 runner 配置以官方文档 Distributed 章节为准。
